# Backend Permission Changes Needed

## Issues Identified and Frontend Fixes Applied

### 1. ✅ Student Login Error Message UX (FIXED)
**Issue**: Students getting "session expired" instead of "invalid credentials" when entering wrong details.

**Frontend Fix**: Updated `components/auth/StudentLoginForm.tsx` to properly handle error messages:
- Added specific handling for "session expired" errors
- Changed generic "Invalid credentials" to more descriptive "Invalid credentials. Please check your email, student code, and PIN."
- Better error classification for rate limits vs credential errors

### 2. ✅ Student 403 Forbidden on Enrollments (FIXED)
**Issue**: Students getting 403 Forbidden when trying to access their own enrollments via `/api/enrollments`.

**Frontend Fix**: 
- Added new API method `getStudentEnrollments()` that calls `/student/me/enrollments` instead of `/enrollments`
- Updated `app/student/my-tutors/page.tsx` to use the student-specific endpoint
- Added `getStudentEnrollmentSessions(enrollmentId)` for student-specific session access

**Backend Changes Needed**:
- Implement `/student/me/enrollments` endpoint that returns only the logged-in student's enrollments
- Implement `/student/me/enrollments/:enrollmentId/sessions` endpoint for student-specific session access
- Ensure students have read access to their own enrollments and sessions
- Current `/enrollments` endpoint appears to be restricted to admins/parents only

### 3. ✅ Parent Enrollment Detail Access (ALREADY WORKING)
**Issue**: Parent can't see specific enrollment detail by ID.

**Frontend Analysis**: The parent enrollment detail access is already correctly implemented:
- Parents call `api.getEnrollments()` which returns all enrollments they have access to
- Parents filter enrollments by their child's studentId
- Parents call `api.getSessions(enrollmentId)` to get sessions for specific enrollments

**Backend Verification Needed**: 
- Ensure `/enrollments` endpoint returns enrollments filtered by parent's access
- Ensure `/sessions?enrollmentId=X` endpoint allows parents to access their children's sessions

### 4. ⚠️ Zoom Session Host Issue (BACKEND ISSUE)
**Issue**: Zoom sessions showing "Waiting for the host to start the meeting" when the tutor should be the host.

**Frontend Analysis**: The frontend correctly creates sessions without specifying host configuration:
- Session creation calls `POST /tutor/sessions` with `{enrollmentId, scheduledAt, durationMinutes}`
- The backend should automatically set the tutor as the Zoom meeting host
- Zoom link is auto-generated by the backend

**Backend Changes Needed**:
- Ensure Zoom meeting creation sets the tutor as the host
- Remove any admin host configuration from session creation
- The session creator (tutor) should automatically be the host
- Zoom meeting should allow participants to join without waiting for host if configured for tutoring sessions

**Recommendations**:
- Set `host_video: true` and `participant_video: true` for tutoring sessions
- Enable `join_before_host: true` for tutoring sessions so students don't wait
- Ensure the tutor's user account is set as the host during Zoom meeting creation

### 5. ⚠️ Session Visibility for Students and Parents (BACKEND ISSUE)
**Issue**: Both student and parent can't see sessions created by tutors.

**Frontend Analysis**: 
- Students use `getStudentSchedule()` which calls `/student/me/schedule`
- Parents use `getSessions(enrollmentId)` which calls `/sessions?enrollmentId=X`
- Both should return sessions for the respective users

**Backend Changes Needed**:
- Ensure `/student/me/schedule` returns all sessions for the student's enrollments
- Ensure `/sessions?enrollmentId=X` allows parents to access their children's sessions
- Verify that tutor-created sessions are properly linked to enrollments
- Check that session status is correctly set (SCHEDULED, COMPLETED, etc.)

### 6. ⚠️ Student Can't See Assigned Tutor (BACKEND ISSUE)
**Issue**: Student can't see tutor assigned to them, but parent can see tutor assigned to their child.

**Frontend Analysis**:
- Students now use `getStudentEnrollments()` which should include tutor assignment data
- The enrollment object should contain `tutorId` and populated `tutor` object
- Parents have access to full enrollment data including tutor assignments

**Backend Changes Needed**:
- Ensure `/student/me/enrollments` returns enrollments with populated tutor data
- Include `tutorId` and `tutor` object in the enrollment response for students
- Verify that the enrollment-to-tutor relationship is properly established
- Check that students have read access to tutor assignment information
